# Ulala

Shared, offline-first travel itinerary PWA for two people.

## Local development

Requirements: Node.js 24+, Docker-compatible runtime, Deno, and Supabase CLI (installed as a dev dependency).

```bash
pnpm install
pnpm supabase start
cp .env.example .env.local
# Fill VITE_SUPABASE_ANON_KEY from `pnpm supabase status -o env`
pnpm dev
```

The Supabase local API runs at `http://127.0.0.1:54321`; Studio runs at `http://127.0.0.1:54323`.

## Useful commands

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm supabase:reset
pnpm functions:check
```

## Notifications

`send-notifications` has its own `deno.json` with pinned npm/JSR imports. Install the Deno VS Code/Cursor extension for editor diagnostics; `.vscode/settings.json` enables it only inside `supabase/functions`.

Web Push requires HTTPS outside localhost, a real push subscription, and VAPID keys. On iOS/iPadOS the app must be installed to the Home Screen before requesting notification permission.

The `send-notifications` Edge Function expects `CRON_SECRET`, `PUSH_CONTACT`, and `VAPID_KEYS` (the JSON generated by `@negrel/webpush`). The public VAPID application-server key goes in `VITE_VAPID_PUBLIC_KEY`; keep the private JWK only in function secrets.

The database creates a per-minute `pg_cron` job, but it stays inert until two Vault secrets exist:

```sql
select vault.create_secret('https://<project-ref>.supabase.co/functions/v1/send-notifications', 'send_notifications_url');
select vault.create_secret('<same value as CRON_SECRET>', 'ulala_cron_secret');
```

For local development, `pnpm functions:serve` loads `supabase/functions/.env.local`; use `http://kong:8000/functions/v1/send-notifications` as the database-side endpoint.

## Cloudflare Pages deployment

Frontend settings:

- Build command: `pnpm build`
- Build output directory: `dist`
- `NODE_VERSION`: `24.21.0`
- `PNPM_VERSION`: `12.8.1`
- `VITE_SUPABASE_URL`: hosted Supabase API URL
- `VITE_SUPABASE_ANON_KEY`: hosted Supabase anon key
- `VITE_VAPID_PUBLIC_KEY`: public VAPID application-server key

`public/_headers` applies security and cache headers; `public/_redirects` provides the SPA fallback. `pnpm-workspace.yaml` declares the root package explicitly so older pnpm/Vercel-compatible tooling does not mistake it for an incomplete monorepo.

Backend setup after creating the hosted Supabase project:

```bash
supabase link --project-ref <project-ref>
supabase db push
supabase functions deploy send-notifications
supabase secrets set CRON_SECRET=<random-secret> VAPID_KEYS=<vapid-json> PUSH_CONTACT=mailto:<email>
```

Then create the Vault secrets shown in the Notifications section using the hosted function URL and the same `CRON_SECRET`.

## CSV columns

Required: `fecha`, `hora_inicio`, `titulo`.
Optional: `hora_fin`, `lugar`, `notas`, `estado`, `reserva`, `traslado_min`, `margen_min`, `recordatorio_min`.

Dates accept `YYYY-MM-DD` or `DD/MM/YYYY`; times accept `H:mm`, `HH:mm`, `HH:mm:ss` or ranges like `17:30-20:30` in `hora_inicio`. Values are interpreted in the trip timezone.

`estado` maps to plan status plus booking status:

- `Confirmado`, `Reservado` → confirmed + booked
- `Por reservar` → confirmed + required
- `Reserva recomendada`/`Reserva sugerida` → confirmed + recommended
- `Sin reserva previa` → confirmed + not required
- `Libre`, `Opcional`, `Plan`, `Idea` → idea
- `Hecho`, `Realizado` → done

An explicit `reserva` column (`sin_definir`, `sin_reserva`, `reserva_sugerida`, `por_reservar`, `reservado`) overrides the booking derived from `estado`. Unknown statuses are rejected with a row error; extra columns are preserved as lines inside `notas`.
